# aioffer-cli

面向中国用户的本地招聘投递助手。你提供 MinerU Key 和视觉模型 API Key，岗位搜索、资料管理、投递编排和浏览器执行均在自己的电脑运行，不需要 AI Offer 账号或企业云端。

> 当前为开发预览版，尚未完成带真实密钥的模型、MinerU 与完整实站投递验收。不要把单测通过当作所有招聘网站可用。尚未发布 npm 安装包，请从源码运行。

## 快速开始

准备 Node.js 22 或更新版本、pnpm、Git 和 Chrome。无需部署 PostgreSQL、Redis 或对象存储。

```bash
git clone --branch feat/local-application-runtime https://github.com/Succaiss-applied-ai/aioffer-cli.git
cd aioffer-cli
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

终端会显示仅供你本人使用的本地链接。浏览器打开后：

1. 填写 MinerU Key，以及一个支持图片输入的模型的厂商、API 地址、模型 ID 和 Key；保存并测试连接。
2. Chrome 地址栏打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展”，加载项目的 `extension/dist` 目录。
3. 刷新本地页面，点击“连接本机插件”。扩展需要读取和操作你发起投递的招聘网页，请先阅读权限提示。
4. 上传简历，明确同意外部解析；核对提取结果，保存已确认的资料版本。
5. 搜索和选择岗位，选择半自动或自动模式，核对本次任务后开始。

详细密钥申请与填写说明见 [模型与 MinerU 配置教程](docs/providers.md)。

## 核心能力

- **本地岗位库**：内置 25,553 条现有岗位快照，离线搜索；来源时间和校验值见 `data/manifest.json`。这不是实时岗位数，也不代表每个网站都支持自动投递。
- **用户自己的模型**：通义千问、豆包、智谱、OpenAI、Claude、Gemini，以及自定义 OpenAI 兼容接口；支持与实测状态分开记录。
- **已确认资料版本**：原文件、提取文本与结构化资料仅在本机保存；确认另存新版本，不覆盖原版本。模型提取结果可能有误，必须人工核对。
- **同一套投递执行器**：继承 AI Offer 的站点驱动、补充资料、登录/验证码交接、停止、中断、提交意图和回执处理。
- **两种提交模式**：半自动每次一个岗位，填写后人工确认最终提交；自动模式一次授权所选批次的最终提交。协议勾选单独授权。

## 命令

```bash
node dist/local/cli.js --help
node dist/local/cli.js doctor
node dist/local/cli.js jobs 前端 上海
node dist/local/cli.js start --no-open
```

`jobs` 后面的词按全文交集检索，显示前 30 条；网页支持独立城市筛选与分页。`doctor` 检查本地运行环境和构建文件，不替代真实 API 测试。

## 哪些数据会离开电脑

“本地运行”不等于“完全不联网”。运行中的外部依赖是：

| 目标 | 发送内容 | 是否需要额外账号 / Key |
| --- | --- | --- |
| MinerU | 用户明确同意解析的 PDF、DOCX 等简历文件 | 用户自己的 MinerU Key；TXT / Markdown 跳过 MinerU |
| 用户选择的视觉模型 | 简历文本、待填事实、必要页面信息和截图 | 用户自己的模型 API Key |
| 招聘网站 | 用户授权提交的资料和附件；用户在网站自行登录 | 视招聘网站要求，不由本项目托管账号 |

MinerU 返回的文件上传/结果存储地址是该服务自身传输链路，不需要你另开对象存储账号。安装和更新还需要访问 GitHub / npm 注册表。模型是否支持所在地区、网络与账户额度，以厂商规则为准。

无 AI Offer 云端回调、账号登录、配额校验或自动遥测。扩展后台的请求只允许本机 `19876` 端口；模型 Key 不交给招聘网页。不要将本地服务通过公网代理暴露出去。

## 本地配置与隐私

| 项目 | 默认值 / 说明 |
| --- | --- |
| 监听地址 | `127.0.0.1:19876`，当前不支持改端口 |
| `AIOFFER_DATA_DIR` | 可选，自定义数据目录；默认用户目录下 `.aioffer-cli` |
| 密钥 | 数据目录中的 `config.json`，本机明文保存；不是系统钥匙串 |
| 文件权限 | CLI 以仅本人可读写的权限创建数据；保护好自己的系统账户 |
| 本地访问链接 | 包含随机访问凭据，不要分享、截图公开或提交到 Git |

示例：

```bash
AIOFFER_DATA_DIR="/你的绝对路径/aioffer-data" pnpm start
```

关闭终端服务后网页不能继续创建任务。中断后重新启动会读取原记录；不会因为重新启动而自动重投结果不明确的任务。不要删除投递历史来绕过重复保护。

## 投递时需要注意

1. 岗位是静态快照，可能失效、重复或存在源数据格式问题。核对企业官网，以真实表单和网站回执为准。
2. 半自动确认绑定当前回读哈希。确认后页面变化或确认过期，会重新要求核对，不能用普通“继续”替代最终确认。
3. 登录和验证码在原招聘标签页完成。不要刷新、关闭正在填写的受控页；这样会停止当前尝试。
4. 缺少真实资料就补充，不让模型编造。无法识别的控件保留明确不支持结果。
5. 只有网站真实回执能代表成功。“点击提交”、HTTP 200、任务排队或模型返回均不是成功依据。
6. 当前重复保护较保守：同一岗位已有记录时不能另建新任务；等待中的任务在原记录继续。不可恢复失败暂需维护者检查，不提供“一键清历史重投”。

## 开发与验证

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm check:cloud
```

测试用模拟服务验证协议与安全边界，不消耗用户真实 Key。部分上游 PostgreSQL 集成测试需要专用测试数据库，默认不运行；本地产品不依赖该数据库。更详细的迁移范围和验收缺口见 [迁移与验收说明](docs/migration.md)。

## 主要目录

| 目录 | 作用 |
| --- | --- |
| `src/local` | 中文 CLI、本地接口、模型与 MinerU 适配、资料和岗位库 |
| `src/gateway` | 继承的投递状态机、设备配对、命令租约与回执 |
| `extension/src` | 浏览器执行器及原站点驱动 |
| `web` | 中文本地操作页面 |
| `data` | 可离线使用的岗位快照与校验清单 |
| `docs/upstream` | 上游路由规则及历史证据，不是本项目验收结论 |
