# AI Offer 招聘小助手 1.0.12 架构

## 1. 生产结构

```text
AI Offer / AI Agent
  ├─ Job Server
  │    岗位采集、知识库、检索、JD、状态与表单 Schema
  └─ Application Gateway
       MCP、设备绑定、批次、命令、视觉 LLM、证据与回调
            │
            ▼
       Chrome 插件
            │
            ▼
       招聘网站投递页
```

生产运行单元为两个 Server 和一个插件。MCP 集成在 Application Gateway 的 `/automation/mcp`；独立 stdio/HTTP MCP 与 localhost Runtime 只用于开发和兼容。

## 2. 职责边界

### AI Offer / AI Agent

意向工作城市的首选/备选来源、实时选项与补充契约见 [意向城市策略](PREFERRED_WORK_CITY_POLICY.md)。

- 管理登录用户、求职偏好、岗位选择和批次级确认；
- 生成标准候选人信息包和短期附件引用；
- 为单城市或多城市岗位提供带来源的 `job.answers`；
- 创建批次、展示人工介入提示、查询状态和记录结果；
- 不直接控制 DOM，不接触 Device Token 或模型 Key。

### Job Server

- 采集公开招聘来源并维护企业、岗位、JD 和投递 URL；
- 提供结构化检索、游标分页、岗位详情和完整库存导出；
- 维护稳定岗位 ID、来源证据、状态和去个人化表单 Schema；
- 不保存候选人完整简历或实际表单答案。

### Application Gateway

- 将 AI Offer 用户无感绑定到本地插件设备；
- 持久化批次、命令、租约、证据、回调和人工续接状态；
- 托管视觉 LLM，并只接收白名单页面观察数据；
- 暴露 `/auto-apply/v1`、`/device-bridge/v1` 与 `/mcp`。

### Chrome 插件

- 领取已确认的具体岗位任务并串行执行；
- 自动任务标签页始终在后台创建和执行；任何站点、控件 Driver 或失败处理都不得激活招聘页、聚焦招聘窗口或改变用户当前标签页；
- 观察、正常上传简历、等待网站自动解析/页面稳定、按 AI Offer 信息包填写和读回；禁止主动调用网站解析；
- 处理动态 DOM、自定义下拉、级联城市、重复字段和必要声明；协议按钮可用时直接确认，受限时以可信滚轮滚到底、等待 10 秒后重试并回读复选框；
- 控件分流先匹配“公司 + 特定控件”例外，其余按真实原生/共享组件类型选择唯一 Driver；同优先级歧义停止，失败不跨 Driver 回退。
  Moka 城市与平面下拉分别使用独立后台组件 Driver，双语字段主标题保持稳定；城市允许真实选项中唯一的前两个汉字匹配，平面下拉只允许完整精确或唯一汉字/拉丁文双语半边匹配，其他字段不放宽。
  Moka 电话区号只有在同一电话字段内同时确认 `code-*` Select 与 `number-*` 手机号输入角色后，才复用平面下拉 Driver 的默认策略：个人、紧急联系人、推荐人及其他人的电话统一执行单一真实选项直接选择、多项只选择唯一 `+86`；缺失或重复 `+86` 保持原值并返回选项不可用。当前岗位精确确认答案优先，人物身份和号码事实继续按原字段隔离，手机号事实及右侧手机号错误不能流入左侧区号动作。
- 登录缺失返回 `failed/login_required`，保留原招聘页供用户登录，解除该任务监听并释放执行槽，用户登录后重新投递；身份核验仍返回明确失败。只有验证码/滑块进入 `waiting_for_user_action`，原标签页由持久监控继续观察。验证码不是终态：验证后可收口为成功、原页关闭失败，或招聘网站投递数量限制失败；
- “预览”文案不能证明动作可逆。首次预览或直接提交的可信指针前都持久化防重意图并安装目标级事件
  探针；控件重建、未观察到 click 或结果不明时保留检查点，不重试预览；
- 后续只有唯一且语义明确的最终确认控件才在同一授权事务内执行；站点本轮明确的字段拒绝可进入
  用户补充/更正流程。禁止 DOM `.click()`、键盘提交、`Page.bringToFront`、刷新或整表重填；
- 已登记提交事务后主动核验 12 秒；未见终态才转入 `waiting_for_site_receipt`，保留精确绑定的原页后台观察
  108 秒并释放主动执行槽；
- 取得明确成功、重复申请或失败证据后先回传；Gateway/AI Offer 确认接收后，才执行插件页清理。登录原页继续保留，不因回执确认或插件重启而关闭；验证码和上传拒绝仍按原规则保留。其他终态关闭插件创建的标签页，用户原本拥有的标签页永不自动关闭。
- 阶段变化立即上报岗位进度，持续处理时每 10 秒续报一次。

## 3. 浏览器执行循环

自动任务的浏览器执行面统一由 `auto-apply-execution-surface.ts` 管理：所有 ATS 的新任务都在明确的
普通 Chrome 窗口中创建 `active:false` 标签，不再使用飞书/小鹏独立 popup 分支，不按 URL 认领旧页。
同一任务续接保留精确绑定原标签；旧版本已暂停在 popup 的任务也不重开或搬移。清理只针对任务标签。
人工主动打开岗位也显式选择普通窗口，只保留 active 标签行为，不再依赖 Chrome 当前窗口。
PageSession 的执行面诊断记录 tabId、windowId、窗口类型及新建/续接来源，不能用诊断替代任务身份核验。

入口编排先启用页面级焦点模拟，再等待异步渲染和通用阶段分类；各站点 Entry Driver 只返回精确入口，
由共享可信指针执行一次点击。小鹏也不再直接调用 DOM `.click()`。模拟在目标页稳定分类后释放，
不激活浏览器标签/窗口，不跨入后续字段 Driver 的调试连接生命周期。初始化或导航失败同样释放连接。

```text
识别页面阶段
→ 任意 HTTP(S) 招聘页：连续两次稳定判定 job_detail / login / application_form；unknown 只等待或失败关闭
→ 小鹏职位详情页：由已登记的小鹏 Application Entry Driver 点击唯一投递入口
→ 飞书职位详情页：由飞书租户 Entry Driver 等待 React 延迟渲染并委托一次可信指针
→ Moka 公开职位详情页：仅在已验证的两个等价“申请职位”按钮同时存在时，由 Moka Entry Driver 委托一次可信指针
→ 其他职位详情页：仅在唯一精确申请控件已被重新验证后，由通用 Entry Driver 委托一次可信指针，否则停止
→ 登录：failed/login_required，保留原执行页并解除任务监听，用户登录后重新投递
→ 验证码：waiting_for_user_action/captcha_required，保留原标签页并释放执行槽
→ 身份核验：failed/identity_verification_required，回传后关闭插件执行页
→ 真实申请表：进入观察与填表
→ 无法识别或入口不唯一：停止并返回 application_entry_not_opened

观察
→ 字段事实规划
→ 控件证据注册表选择唯一 Driver
→ 通用原生 | 后台站点确定性 | 未支持
→ 执行动作
→ 等待页面稳定并重新观察
→ 逐字段读回
→ 下一步 / 人工接管 / 最终提交 / 站点确认弹窗 / 终态识别
```

职位详情页与最终提交页是两个不同安全阶段。页面阶段分类器是跨站点的强制前置门禁，不属于任何
站点 Driver：初始加载、URL/hash 变化、SPA 根节点重建，以及入口、登录、验证码、下一步、协议和
提交动作后的重新观察都必须重新分类。稳定性同时绑定 URL 与页面状态指纹；同一 URL 的 DOM 状态
变化会清零稳定读数。只有连续两次稳定的 `application_form` 可以进入字段规划、填写、审计和提交，
`unknown` 不能作为空表单继续。

入口执行继续保持“小鹏专用、飞书租户专用、Moka 专用、其他站点严格通用”的边界。通用入口只
接受唯一、可见、启用且精确申请文案的控件；它不会直接使用 DOM `.click()`，而是在同一 URL、同一控件和
实时命中点再次校验后，才发送一次可信指针。Moka 只对真实页面已验证的“两枚结构等价入口”以及同一
操作区唯一“申请职位”主按钮登记例外，其他数量或结构变化均停止；飞书租户接受 `index`、`campus` 和
`/<tenantScope>/position/.../detail` 的已登记职位详情路径，小鹏继续接受 `campus` 与 `index` 路径。跳转后必须重新观察，不能沿用详情页
快照，也不能把详情页入口交给最终提交执行器。入口不唯一或目标状态不明确时停止，任何
`formDetected=false` 的页面都不能进入填写收敛、最终确认或最终提交。

跳转后的 Application Page State Classifier 必须保持跨站点通用，不存在小鹏、Moka 或其他 ATS
专用登录 Driver。分类器只接受页面级证据：登录 URL、可见验证码登录表单、密码登录表单，或
“登录后继续申请/投递”且页面不存在可用申请表。公开职位详情页页眉里的孤立“登录”链接不是
登录墙证据。命中登录后统一返回 `failed / login_required`，不得改写成填表错误或提交错误。
详情页、登录页和 `/campus/resume/{jobId}/apply` 仍绑定到同一岗位 PageSession。

字段事实规划负责决定“填什么”，控件 Driver 负责决定“如何操作”。控件执行前必须完成唯一分流，不允许先尝试通用 Driver、失败后再换另一 Driver。每次 DOM 重建后重新定位，不能缓存失效元素或依赖顺序 `fieldId`。

每个已登记控件同时声明自己的权威回读策略。原生文本、招聘页返回的原始选项、单城市、省市区层级、
日期/年月和勾选状态分别比较；专用 Driver 的结果不会再被通用字符串全等二次推翻。行政区字段按答案
来源区分：当前招聘页返回的选项保持展示精确匹配，AI Offer 自有地区分类只折叠行政后缀和分隔符，
并继续要求实际省、市、区层级一致。日期回读还携带日或月精度：固定精度 Driver 优先，其次使用填写
指令和原生控件类型，绝不因为页面少回读了“日”而自动降低精度；外层填写循环复用同一
策略。

xTool 的 Formily 重复经历原生字段使用独立 `xtool.formily-repeat-native.v1`。页面会在新增经历和字段事件后
重建整条卡片，并重复使用 DOM id；Driver 因此只按区块根、重复项序号和字段语义定位，单次写入后从新
节点回读。飞书年月区间使用 `feishu.month-period.trusted-pointer.v3`，点击前按同一稳定身份重绑并执行
一次后台即时滚动，视口命中成立后才发送可信指针。飞书 Formily 字段方言先把
`.ud-formily-item` 的标签、重复项身份、必填标记和 `.ud-formily-item-error-help` 映射进统一字段快照；
readonly search Select 再由 `feishu.formily-flat-select.trusted-pointer.v1` 按同一稳定身份执行唯一平面弹层、
精确选项和展示值/弹层/局部校验回读。字段方言只负责观察，不能直接决定或执行 Driver；这些链路都不
刷新页面或激活招聘标签页。

可确定事实按页面观察顺序一次执行一个字段，并在每次权威回读后重新观察；不把页面底部必填字段提前到
前面的工作/项目经历之前。当前页面提供 `stableFieldKey` 时，补充答案与执行定位只能使用该稳定身份，
不能再使用同一观察中的 `field-N` 或旧 selector。稳定目标消失或语义不一致时立即返回字段错误，禁止写入
邻近控件。

同一 ATS 内若租户弹层状态机不同，使用更窄的 URL、字段语义和 DOM 签名登记独立 Driver，并排在
ATS 通用登记之前。例如 tap4fun 出生日期初始为日历面板、年份选择后仍返回日历，且向上弹层会被固定
导航覆盖，因此由租户专用 Driver 走年/月/日完整状态机；它的失败不会回退到通用 Moka 日期 Driver。
日历 Driver 共享目标级视口策略：精度只由控件自己的 type、时间布局或 placeholder 决定；打开和每次
面板变化后收集当前阶段所有后续动作目标的真实矩形，结合横向相交的 fixed/sticky 顶部遮挡和视口边界
计算剩余有符号位移。窗口与最近可滚动祖先每次只消耗视口有界小步，再重新观察全部目标；只有方向一致且
剩余遮挡严格缩小时继续，目标全部命中后才操作。弹层外壳可以部分出界，但动作目标无法容纳、页面不动、
方向反复、遮挡不再缩小、达到安全步数上限或安全区内命中失败时必须停止，不能固定距离滚动、盲点或降低精度。
Moka 通用日历不把企业自定义字段名作为硬门槛，而以 URL、readonly 输入、Dropdown 祖先和日期包装类/
placeholder 建立候选；观察器把控件及有限祖先类名带入规划期，确保结构化日期不会先落入普通键盘路径。
候选控件安全打开后还要执行面板结构准入：先把当前控件内有祖先包含关系的 Dropdown / panel-menu
包装节点归并为一个外层可见容器，不能用原始 DOM 命中数量判断弹层数量。只有唯一独立弹层形成完整日网格、月份集合或年份范围才确认通用
Driver，打开本身不等于路由成功。已确认租户字段的窄路由可直接确认字段归属和精度，但仍执行面板状态、
目标命中与最终回读验证。
Garena 租户 148076 的已填出生年月面板若显示 `0年`，仍留在同一 Moka v9 Driver：精确字段、月精度和
十二月份结构成立后仅允许一次已验真的年份导航，回读正常 `1901年` 且旧值未改变才继续选择目标年月。
这不是有效零年份或通用恢复规则；其他租户、歧义和未确认转移都停止。打开状态与年月可解析状态分别
观察，已打开但尚不可解析的弹层不会再次点击输入框而被关闭。最终仍使用结构化年月及局部校验回读。
真实生产记录已经证明存在特殊状态机或精度约束时，再用“精确租户 URL + 稳定字段键 + 控件签名”登记
更窄路由，并排在该结构通用路由之前。只有 `YYYY-MM` 值而通用控件证据不能证明月精度时，字段仍按
日历隔离但在点击前失败关闭；不得依据另一租户的同名字段或稳定键继承精度。

字段事实规划采用严格语义匹配。空的非必填字段默认不进入确定性预填或视觉模型输入；简历推导事实、
候选人信息包和跨岗位复用资料即使能与字段语义匹配，也不能触发新增可选内容。只有用户已经为当前岗位
的当前字段明确确认答案，或为当前岗位明确确认意向城市等同语义岗位答案时，该非必填字段才允许进入
规划。简历中的教育、工作、实习或项目条数也不能触发页面“添加/新增”动作；动态区块仅保留站点原有
条目，后续若站点明确暴露必填字段，再按最小必填范围处理。值来自信息包并不代表可用于任意字段。候选人本人姓名、电话、邮箱不得用于外部推荐人、紧急联系人
等第三方字段。观察器必须保留“紧急联系人姓名”等完整可见语义并归入 `third_party` 区块，不能因
placeholder 含“姓名/电话/邮箱”而降级成候选人本人字段；必填第三方字段即使已非空，只要值与候选人
本人身份相同且没有当前岗位或用户确认的精确字段事实，仍按污染后的缺失信息一次性回传 AI Offer。
已有且不同的人工填写值保持不动，精确补充事实则可确定性覆盖旧错误值。飞书“与公司员工是否有亲属关系（如有）”使用独立 `relation` 区块；页面出现必填校验
时，“姓名、部门/职位、与本人关系”作为三个结构化缺失字段一次性回传 AI Offer，不能借用候选人身份
或模型猜测。选择类字段还要求页面真实选项兼容该事实，否则事实视为当前页面不可用。

填写失败策略按字段必填性隔离。未获当前岗位明确确认的空非必填字段在规划和执行两层直接跳过，不产生
页面写入；页面已有的非必填值保持不变。必填字段只按 `stableFieldKey + expectedValue` 累计自身失败次数；
非读回不确定类的普通必填失败仍受字段级熔断限制，不能把其他字段的失败继承过来。
已登记的专用 Driver 仍遵循一次性契约且不得伪报成功；空回读/提交未确认的编排处理见下文。
获当前岗位明确确认的非必填字段若首次执行
失败、控件消失或回读不一致，立即加入当前任务排除集，不重试、不参与必填熔断，也不阻塞最终提交。

自动提交采用统一站点校验驱动：初始规划仅保留可信事实，不因信息包没有某必填答案而提前阻断，
也不让模型补造答案。填写完可执行字段后直接进入已授权提交，不再运行第二次字段完整性或模型审计。
已精确绑定的字段回读不确定/不一致只记录结果，不把失败伪报为成功，也不反复操作同一控件；
错误目标、语义冲突、未登记控件等执行错误仍明确报告，唯一 Driver 与第三方身份隔离不变。
城市的实时选项只是约束，不因选项只有一个就跳过候选事实优先级或用户确认。

本次可信点击后出现新的字段错误、同文案局部错误重新断言或原生 invalid，先冻结本次明确拒绝的稳定
字段集合，不重新判断其必填性。按页面顺序将集合分为“有兼容事实”与“无事实”：前者每项只调用唯一已登记 Driver 一次，
允许仅这些精确字段覆盖网站预填旧值并权威回读；后者保持不动。一个可复填字段都没有时直接返回第一次全部拒绝集，不重复点击。
至少一项修复回读成功时只再提交一次。第二次可信点击仍返回字段错误时，无论是本轮新出现的条件字段、无事实字段、非空非法值，
还是信息包已有答案，都一次性返回第二次点击的全部明确拒绝字段，绝不第三次提交。
定向复填不刷新/重开页面、不重传或解析简历、不重跑完整表单、不扩展字段、不切换 Driver 或调用模型造值。
真实下拉选项和字段错误随请求返回；某字段选项发现失败不吞掉其余请求。
字段拒绝或缺失信息先回传 AI Offer，确认接收后关闭插件执行页。用户补充信息并明确发起的新尝试使用新的后台页和正常上传/填写流程，不把旧页刷新或整表重填当作兜底。若任务运行在用户原本拥有且仍存活的页面，才允许按冻结字段范围续填。每次用户补充续投、字段提交及网站拒绝后都重建稳定快照；字段身份/顺序、控件类型、当前值、实时选项、必填与校验状态任一变化都使旧快照失效。
静止旧红字单独不是新拒绝。新的可信提交后只保留两个窄例外：同一精确控件仍为空且仍持有字段内必填/缺失错误；或唯一允许的第二次提交后，第一次冻结稳定键中的字段内错误仍存在。
飞书 Formily 的“姓名为必填”“学历为必填”等字段名式文案属于字段根内的必填错误；主动与被动监控使用
同一拒绝字段收集器，不能因错误出现在 12 秒/108 秒交界处而丢失补充请求。
冻结集外的普通旧错误、全局网络错误和无响应不能清除防重检查点。

直接提交或明确最终确认后采用 12 秒主动 + 108 秒被动监控。被动监控保留原点击的字段基线与事件探针，
迟到字段拒绝经 Gateway 的 site_validation_rejected 回调转换为 waiting_for_user_action / missing_information。
监控只读、不操作控件、不占后续岗位执行槽；回调失败先保存待回传信息，再重试。
未知预览结果仍保持未知和防重检查点，不把预览文案当作真实提交证明。
补充字段/答案接口统一最多 200 项，不再在 40 项处静默截断。Gateway 与插件需要配套部署。
详见 [SITE_VALIDATION_HANDOFF_POLICY.md](SITE_VALIDATION_HANDOFF_POLICY.md)。

批量任务的提交意图在可信指针前落盘，包括“预览并提交”；保存失败不点击，崩溃后仅核验。
自动批次与显式 Bridge 提交共用可信
指针事务和回执识别，旧合成点击函数仅留作进程内兼容测试，不再注入招聘页面。回执要求完整可见的
肯定语句或登记 URL，不做“已收到 / submitted / successfully”任意子串匹配。按钮重绘不算二次确认，
通知弹窗的“确定”不算投递确认。提交按钮禁用时明确报告，不强制点击或猜测缺失答案。

缺失信息暂停保存待修复稳定键，但插件执行页在 AI Offer 接收状态后关闭；补充后的新尝试在新页面执行正常上传和填写。只有用户原本拥有且仍存活的页面可继续原范围。无真实选项的答案与
其余缺失请求一起返回。已知目标消失但缺乏条件解除证据时保守停止，不把消失等同于修复成功。
籍贯 Driver 已在 JXW 真实页验证后台焦点模拟与可信指针的完整省市区选择及语义回读，登记为
`requiresForeground=false / background_tab`。成功和异常都释放焦点模拟并断开自己的调试连接；
失败不激活标签、不刷新或换 Driver。预览无 click 的前台重试也已删除。

下拉、组合框、自动完成列表和级联菜单是 option-only 控件。执行器只能打开控件并点击实时存在的
唯一兼容选项；禁止向内部 input 键盘输入、按 Enter 造出选中态、直接写入/清空 DOM value，或回退
到普通文本输入。没有匹配选项时保持页面字段不变，必填项返回补充信息或控件错误，非必填项跳过。

“补充信息”与“控件错误”由现场证据分流：只有唯一弹层已打开、并读取到至少一个有效叶子选项时，
目标值缺失才是 `option-unavailable` 业务状态；必填项把实时选项返回 AI Offer 重新选择。弹层未打开、
选项归属不唯一、点击或回读失败仍是 Driver 错误。两条路径都不允许键盘、DOM 强写或近似匹配。

控件分流的唯一来源是可序列化结构化登记表。每条登记固定声明站点名称/URL 家族、字段语义、控件类型/DOM 签名和唯一 Driver；每次运行再生成 `control-adapter-diagnostic.v1`，将本次实际 `siteName`、`fieldName`、`controlType` 与登记项绑定。该诊断随视觉请求、插件执行记录和终态失败 JSON 传递，AI Offer 不从错误文案或 `adapterCode` 猜测控件身份。

原生、跨站点可复用且可权威回读的控件进入通用 Driver；依赖 ATS DOM 和稳定事件序列的控件进入后台站点确定性 Driver。自动控件注册表不再允许 `foreground_visual` 或 `focused_user_window`，证据不足的自定义必填控件必须停止并返回 `unsupported_required_control`，不能通过抢焦点补救。Codex 修复控件时必须遵循 [CONTROL_ADAPTER_ROUTING_POLICY.md](CONTROL_ADAPTER_ROUTING_POLICY.md)。

DeepSeek 意向工作城市命中 `moka.deepseek.location.trusted-focus.v4` 后进入不可回退的 `detect → prepare_open → open → select → optional commit → readback` 状态机。`prepare_open` 隔离执行唯一一次即时滚动和双帧稳定；打开前安装 MutationObserver，之后所有弹层轮询均为只读。Driver 对后台调试目标启用焦点模拟但不调用 `Page.bringToFront`，打开、城市叶子和必要失焦提交均使用点击前实时验证的唯一可信指针序列，不写 input value。每类动作最多一次；成功必须同时满足展示值一致、弹层关闭和字段校验清除。目标不存在但实时选项可信时返回 `leaf_missing + availableOptions` 并进入业务补充；其他失败返回 `driverStage`、细分 `driverFailureCode`、生命周期以及零重试/零刷新动作账本。

Linctex 意向工作城市命中 `moka.linctex.location.trusted-focus.v1`。当信息包没有用户确认的城市事实时，
插件在同一精确 Driver 中执行只读选项探测：一次可信指针打开唯一城市控件，只收集当前弹层的
`Menu-content-item → option-label` 城市叶子，再点击同字段唯一非交互标题关闭弹层，并确认展示值仍为空。
这些选项进入 `required-field-request.v1`，由 AI Offer 渲染补充信息下拉框。只有用户确认选项并写回原岗位后，
插件才重新排队并执行城市叶子选择、必要的标题失焦提交以及展示值/弹层/校验三条件回读；岗位地点不能
推导候选人意向，探测失败也不能回退到通用合成事件、键盘或 DOM 值写入。

Moka 招聘信息来源字段命中 `moka.recruiting-source.trusted-focus.v1` 后进入独立的后台站点确定性
Driver。该 React Select 的原生 input 在已选择时仍为空，展示值也可能先于字段校验提交；因此只有精确
展示值、弹层关闭和字段局部校验清除同时成立才算完成。若选择后仍有必填错误，Driver 只对同字段唯一
标题执行一次可信指针失焦提交并重新观察；失败时不进入最终提交，也不回退到通用 Moka 下拉逻辑。

协议动作命中 `generic.consent-confirmation.trusted-pointer.v1` 后进入跨站点后台 Driver。它只接受明确
协议语义与唯一原生/ARIA 复选框；通用“确认”仅允许出现在已识别协议弹窗内。确认按钮可用时直接
执行，不能确认时滚动弹窗或跨域 iframe 到底并等待 10 秒后重试；最终以弹窗关闭和复选框 checked 状态
回读，不把确认协议与预览/最终提交混为同一动作。

Gateway 不执行失败兜底。`retryBeforeSubmit` 仅作为旧客户端兼容字段接收并归一化为 `0`；插件返回的状态、`reasonCode`、证据和 Driver 阶段原样成为岗位终态，然后批次继续处理下一个岗位。

## 4. 站点路由

- `moka.deepseek.v1`：DeepSeek/Moka 专用入口；
- `moka.v2`：其他 Moka 租户；
- `feishu.xiaopeng.v1`：小鹏飞书招聘；
- `generic.web.v1`：其他有效 HTTP(S) 投递链接的通用自适应入口。

未知站点不再被硬编码白名单直接拒绝。全量准入表示“允许真实尝试”，不表示全部岗位已经验收成功。

## 5. 批量投递状态机

```text
queued
→ running
→ failed/login_required ──用户登录后重新投递──→ 新任务
→ waiting_for_user_action/captcha_required ──用户完成验证，后台检测站点终态──→ succeeded | already_applied
                                             └─用户关闭原页──→ failed/captcha_tab_closed
                                             └─站点提示近期投递过多/达到上限──→ failed/site_application_limit_reached
→ failed/identity_verification_required ──用户处理后重新投递──→ 新任务
→ waiting_for_user_action/missing_information ──用户补充信息并重新投递──→ 新任务
→ waiting_for_site_receipt/submission_receipt_pending ──20–40 秒迟到成功页──→ succeeded | already_applied
                                                       ├─用户关闭原页──→ failed/submission_receipt_tab_closed
                                                       └─累计约 120 秒无成功回执──→ failed/site_success_not_observed
→ succeeded | already_applied | failed | outcome_unknown
```

同一设备的主动表单执行并发数固定为 1，避免串表。验证码等待和站点迟到回执等待都不占主动执行槽：
当前命令回执后，Gateway 立即派发下一条排队岗位；浏览器只读监控精确绑定的原页。监控不会刷新、
重开、重填或重复提交，结果不确定时不得自动重复提交。

验证码完成后的站点策略弹窗使用跨站点只读识别：可见文本必须同时包含岗位/申请语义、数量或频率限制、
时间窗口或等待边界。普通加载提示、验证码提示、项目经历日期和“投递成功后等待通知”不能触发该终态。
明确登记的成功 URL 优先于页面残留文本。命中后插件先向 Gateway 回传原站点提示，Gateway 将岗位置为
`failed/site_application_limit_reached`；AI Offer 接收终态后才允许关闭插件创建的标签页。该失败不进入
必填信息补充，不刷新页面，也不自动重投。

## 6. 授权与人工边界

- 用户在 AI Offer 确认完整批次，一次确认覆盖该批次岗位；
- `allowAutomaticFinalSubmit=true` 后，插件可完成最终提交，无需逐岗位二次确认；
- 最终点击后出现的信息不一致/再次确认弹窗属于同一提交事务；插件只点击弹窗内唯一、精确的确认控件，
  并继续等待网站成功证据；
- `allowConsentClick=true` 后，插件可处理投递所需的明确协议、声明和真实性确认；
- 登录密码、短信验证码、滑块、人脸识别和身份验证由用户操作；
- 登录缺失结束本次尝试，保留原页供用户登录，不自动续投；身份核验仍在 AI Offer 接收结果后关闭插件执行页。验证码由用户在原页完成，成功由后台自动回写，用户直接关闭验证码页则只失败对应岗位；
- 未获得批次授权或未获得明确成功证据时，不能报告成功。

## 7. 持久化与凭证

1.0.12 的多副本 Gateway 以 PostgreSQL 共享批次、命令、设备、配对凭证、任务事件和回调 outbox；短事务只提交数据库状态与命令，不等待浏览器、模型或外部回调。API 与后台 worker 分离，worker 主动回收超时及孤立命令。Job Server 的既有岗位数据存储保持独立，不能把其 JSON 文件复制方式用于共享 Gateway 执行状态。

插件使用 `chrome.storage.local` 保存设备绑定、页面会话及按命令隔离的持久化回执。模型、服务和 Device 凭证互相分离；模型 Key 只保存在 Gateway 环境变量中。JSON Gateway 保留单实例兼容模式；Redis、Native Messaging Host 和宿主仓储适配不是本版多副本方案的必要依赖。迁移与环境实际启用状态以部署验收为准。


## 补充资料读取与续投

补充资料以 AiOffer 后端的事务快照为准。资料编辑不生成 Application Gateway 同步任务，也不逐个改写历史批次。新批次只携带 `candidate.applicationProfileUrl` 和版本元数据；插件声明 `candidate_profile_fetch.v1` 才可接收此类批次。

插件每次开始岗位执行时，从已绑定的 AiOffer 产品域名直接读取 `GET /api/v1/gateway/plugin-execution-profile`，使用产品 HttpOnly 登录 Cookie 和通过可信页面桥传入的浏览器实例标识。这个路径属于 AiOffer 对外鉴权入口，并非 Recruiting Application Gateway。DeviceToken 不发送到 AiOffer。读取校验用户、设备、批次、岗位、有效期和简历版本；单次执行使用同一份资料快照。失败时不回退旧资料、不执行该岗位的表单填写，既有调度继续处理其他岗位。

旧批次没有读取 URL 时，可在产品页连接/唤醒后通过本地保存的产品来源和 Gateway 批次 ID 解析；尚未经过新页面连接的旧绑定继续原快照兼容行为。部署前须刷新产品页并重新连接新版插件。已有运行中的岗位不热替换其执行快照。

“保存并继续”先将资料、岗位精确答案和幂等回执原子写入 AiOffer，返回 `deliveryPending`；仅该岗位的继续指令由后台交给 Application Gateway，重试前仍检查原问题指纹与停止围栏。Web 分别显示已保存和待续投，续投不可用不能回报为保存失败。
