# 使用与排障

第一次使用先看 [README 快速开始](../README.md#快速开始)，密钥申请看 [模型与 MinerU 配置教程](providers.md)。本文保留日常使用、故障处理和开发验证的详细说明。

## 常用命令

在项目根目录安装依赖并构建后运行：

```bash
node dist/local/cli.js --help
node dist/local/cli.js doctor
node dist/local/cli.js jobs 前端 上海
node dist/local/cli.js start --no-open
```

| 命令 | 作用 |
| --- | --- |
| `--help` | 查看中文帮助 |
| `doctor` | 检查 Node.js、岗位快照、构建文件和插件协议版本；不代替真实 API 调用测试 |
| `jobs 前端 上海` | 按全文交集搜索，显示前 30 条；网页另有城市筛选与分页 |
| `start --no-open` | 启动本地服务但不自动打开浏览器；终端显示含访问凭据的链接 |

不要同时启动多个实例。

## 本地配置与隐私

| 配置 | 默认值 / 说明 |
| --- | --- |
| 监听地址 | `127.0.0.1:19876`，当前不能改端口 |
| `AIOFFER_DATA_DIR` | 可选；默认是用户目录下的 `.aioffer-cli` |
| 模型与 MinerU 密钥 | 数据目录内的 `config.json`，本机明文保存；不是系统钥匙串 |
| 文件权限 | CLI 以仅本人可读写的权限创建数据，仍需保护好系统账户 |
| 访问凭据 | 本地链接含随机凭据，不要分享、截图公开或提交到 Git |

在 macOS / Linux 上，用项目目录旁边的独立文件夹保存数据：

```bash
AIOFFER_DATA_DIR="$PWD/../aioffer-local-data" pnpm start
```

在 Windows PowerShell 中：

```powershell
$env:AIOFFER_DATA_DIR = Join-Path $PWD "../aioffer-local-data"
pnpm start
```

这些示例设置同一个已实现的环境变量；macOS 启动已验收，Windows 示例未在 Windows 实机执行。自定义目录包含密钥和简历，**不要提交到仓库**；建议在仓库之外选择你自己的数据目录。

更换模型 API 地址或厂商时需重新填写 Key，避免向新地址发送旧厂商的密钥。要撤销 Key，请先在对应厂商控制台禁用，再更新本地配置。

数据不是绝不外发：简历解析会调用 MinerU 和所选模型；填写与附件上传会接触招聘网站。即使没有最终投递，前面的操作也可能已经传输资料。见 [README 数据去向](../README.md#本地运行哪些数据仍会外发)。

## 插件连接

1. 先执行 `pnpm build`，确认生成 `extension/dist`。
2. Chrome 打开 `chrome://extensions`，开启开发者模式，加载该目录。
3. 停用旧版 AI Offer 招聘插件，避免多个插件争抢页面桥接。
4. 在 Chrome 打开终端提供的本地工作台链接，刷新后点击「连接本机插件」。

工作台在发送配对凭据前会检查插件身份，旧云端插件不能用作本地执行器。不要通过降低兼容性检查来强行连接旧插件。

更新源码后重新 `pnpm install --frozen-lockfile`、`pnpm build`；如果更新包含插件代码，在 Chrome 扩展管理页点该扩展的重新加载，再刷新工作台。仅本地界面或服务改动不意味着必须重装插件。

## 确认资料和附件

- PDF / DOCX 交给 MinerU；TXT / Markdown 直接读取文本，不调用 MinerU，但仍需同意向模型发送资料。
- 核对结构化资料中的姓名、联系方式、教育、经历等；当前是 JSON 编辑器，修改时保持有效 JSON。
- 可以添加证件照、作品集等附件，明确用途后再确认资料版本。
- 确认会保存新的不可变版本，不覆盖原版本；后续任务使用所选的已确认版本。
- 不要让模型编造经历、学历、联系方式，未提供事实就补充真实资料或停止。

每份文件限制 20 MB，MinerU 解析等待最多 5 分钟；这是产品限制，不是厂商套餐承诺。超时或限额问题见 [配置教程](providers.md#第一步申请-mineru-key)。

## 投递、接手和重试

### 先核对岗位

岗位库是静态快照，不会自动更新。岗位可能下线、重复或有源数据格式问题；以企业官网为准。适配器存在不意味着每个表单都能自动完成。

### 人工确认最终提交

半自动确认绑定当前页面回读哈希。确认后页面变化或确认过期，会要求重新核对，不能用普通「继续」替代最终确认。自动模式在创建批次时单独授权所选岗位的最终提交；招聘网站协议勾选仍是另一项权限。

只有网站真实回执能代表成功。按钮被点击、HTTP 200、任务排队、模型返回均不是成功证据。停止任务不等于撤回已提交的申请。

### 登录和验证码

在原招聘标签页完成。不要刷新或关闭正在填写的受控页面，这会停止当前尝试。工具不能保证在所有登录、验证码、缺失字段或复杂控件处自动恢复。

明确的提交前登录失败，会在记录显示「登录完成，重新尝试此岗位」：

1. 先在原招聘页面完成登录。
2. 回工作台核对原岗位、设备、资料和模式，再勾选重试确认。
3. 创建新的尝试，保留原失败记录。自动模式的重试会再次请求最终提交授权。

已获最终提交许可、结果不明确、已停止或无法判断是否提交过的任务，不开放这个重试入口。旧版自动任务也可能因证据不足被拒绝。**不要删除历史或切换模式绕过重复投递保护。**

## 启动和退出

终端停止服务后，网页不能继续创建任务。重启会读取原记录，但不会因此自动重投结果不明确的任务。

异常退出留下的运行锁，会在下一次启动且确认旧进程不存在后恢复。若端口被占用、锁的进程仍存活或锁内容异常，程序会拒绝启动。

遇到启动失败：

1. 检查是否还有原终端或其他实例正在运行，优先正常退出旧实例。
2. 确认 `19876` 没有被其他程序使用。
3. 保留原数据和错误信息，不要强删锁、配置或投递历史。
4. 用不含个人资料和凭据的报错 [提交 Issue](https://github.com/Succaiss-applied-ai/aioffer-cli/issues/new)。

## 开发与验证

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm check:cloud
pnpm test:cli
```

`test:cli` 需要先构建，并保持本机 `19876` 端口空闲。它在临时目录启动独立进程，验证重复启动、异常退出恢复、在途请求排空期间持锁和正常退出；不读取用户密钥，也不会主动停止你已运行的服务。

协议与安全边界测试使用模拟服务，不消耗真实 Key。部分上游 PostgreSQL 集成测试需要专用测试数据库，默认不运行；本地产品运行不依赖该数据库。

每次验证应分别说明源码、自动化测试、构建和真实网站结果。历史上游记录不等于本项目已通过验收；详见 [迁移与验收说明](migration.md) 和 [开发约束](../AGENTS.md)。
