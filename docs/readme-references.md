## 采用的组织方式

1. **首屏说人话**：一句话解释解决的重复劳动，给出快速开始、配置和反馈入口。原创 SVG 只做品牌展示，不冒充真实界面截图。
2. **先让用户完成一次**：源码运行、加载扩展、配置模型、核对简历、半自动处理一个岗位；不承诺尚不存在的一键安装包。
3. **选择用表格讲清楚**：半自动与自动、模型适配与真实验收、哪些数据会外发，分别比较。
4. **首页与手册分层**：README 服务首次接触项目的人，排障、配置细节和命令迁入 [使用指南](usage.md)；风险摘要不藏起来。
5. **社区有实际下一步**：Issue 负责可追踪的问题，贡献指南承接代码与文档；Star / Watch 只作为可选支持。
6. **保留可核实的边界**：静态岗位数链接校验清单；实站验证链接对应 PR；不宣传“全站适配”“全程无人值守”或“保证拿 Offer”。

## 微信入口的发布条件

参考 doocs/md 的失效兜底与 moredoc、CowAgent 的联系人拉群方式，README「交流与共建」中的微信入口遵循以下要求：

- 清晰说明群里交流什么，例如安装、官网适配、Bug 反馈；
- 项目方确认可公开的二维码或微信号，备注词统一为项目名；
- 二维码失效时的备用入口；不要只有一张会过期的图片；
- 保留 Issue 入口，不要求加群后才能使用或获取教程；
- 禁止在群里收集真实简历、API Key、Cookie 或验证码。

项目方已提供并授权公开「aioffer-cli 沟通反馈4群」二维码，并确认来自企业微信「客户群 → 加入群聊 → 通过二维码加入群聊」入口。README 使用该长期活码，原图保存在 `docs/assets/wecom-group-4.jpg`，不使用有固定到期日的普通群二维码。群满或入口不可用时通过 Issue 反馈；长期活码不代表删除配置、解散群或账号受限后仍可用，也未复制其他项目的二维码。
